# SWMM 5.2.4 and 5.3.0: bugs found in the code review

October 2026

## Summary

This repository is a code review of the legacy EPA SWMM engine in two versions, **5.2.4** (EPA's current release) and **5.3.0** (the legacy engine that OpenSWMM maintains), with every fix also carried into **OpenSWMM 6.0.0**, the C++ engine that is designed to reproduce the legacy results. It found **200 distinct defects**: 57 numerical errors, 23 conceptual and formulation issues, 19 boundary-condition issues, 62 input, report and output-file issues, 21 crashes or undefined behaviour, and 18 toolkit API issues. The first three groups, 99 issues, change simulation results, and in most of them nothing warns the user: often the only sign is a continuity error in the report, and in several the continuity error is wrong too.

Every issue has its own folder with a write-up, input files, a test for each engine and fix patches:

- Each test is run against **5.2.4**, **5.3.0** and **6.0.0**. It shows the bug on every engine that has it and passes on every engine that does not.
- Each issue has a patch for **5.3.0** and a patch for **6.0.0** wherever that engine is affected. With them, the tests pass on both engines, and wherever both were affected the patched engines print the same numbers. 5.2.4 is reviewed but not patched; 8 issues exist only in 5.2.4 and were already fixed in 5.3.0 and 6.0.0.
- All 325 patches apply together, and with all of them applied every test passes on both engines. OpenSWMM's own unit tests (192 test programs, built with the same sanitizers) have no new failures with every patch applied; five 6.0.0 patches also update the unit tests that pinned the behaviour they fix, and the 12 programs that fail with or without the patches are listed, with their causes, in verification.md.

[verification.md](verification.md) has the results, and [Reproducing the issues](reproducing.md) explains how to run the tests.

**How they were found.** The three engines were built with AddressSanitizer and UndefinedBehaviorSanitizer. Ten reviewers each took a part of the engine (dynamic wave; links, nodes and routing; cross-sections, tables and inlets; runoff, infiltration and groundwater; snow, climate, gages, RDII and LID; water quality; input, hot start and interface files; report and output; toolkit API and control rules) and read it line by line in both versions, diffing 5.2.4 against 5.3.0. A sanitizer sweep ran the 73 decks of the SWMM regression suite and 176 decks from the OpenSWMM repository through both legacy engines, and a fuzzer ran 3,603 mutated input files and 240 mutated rain files. Known problems recorded in the OpenSWMM project notes were re-checked against the code. Every candidate was then confirmed by writing a minimal input file and a test that checks the correct answer from first principles (an analytic solution, a conservation law, the documented rule), and a fix. About 250 candidates went in; duplicates were merged and 20 that did not hold up were dropped ([id-map.md](id-map.md) lists them all). Defects noticed along the way but not written up are in [further-findings.md](further-findings.md).

**Suggested order for a release:**

1. **Regressions in 5.3.0**, before 5.3.0 ships: [NUM-01](1-numerical/NUM-01-dry-conduit-quality-nan/), [NUM-02](1-numerical/NUM-02-inlet-backflow-all-inlets-one-bucket/), [NUM-45](1-numerical/NUM-45-dry-node-reports-mass-rate-as-concentration/), [CON-03](2-conceptual/CON-03-lid-runon-to-every-partial-unit/), [CON-04](2-conceptual/CON-04-covered-barrel-returns-rain-over-all-lids/), [BND-01](3-boundary/BND-01-free-outfall-below-regulator-gets-crest-depth/), [IO-39](4-io/IO-39-input-warnings-not-counted/), [IO-43](4-io/IO-43-dated-hotstart-save-time/), [IO-44](4-io/IO-44-hotstart-modified-horton-state/), [CRASH-11](5-crashes/CRASH-11-averages-report-out-of-bounds/), [CRASH-12](5-crashes/CRASH-12-steady-link-quality-node-index/), [CRASH-14](5-crashes/CRASH-14-getcount-getindex-object-type/), [API-03](6-api/API-03-api-error-messages-empty/). Thirteen issues trace to one commit, 5b87a2b5 ("WIP API bindings for pollutants"), which added the 5.3.0 pollutant and subcatchment toolkit functions: [NUM-01](1-numerical/NUM-01-dry-conduit-quality-nan/), [NUM-45](1-numerical/NUM-45-dry-node-reports-mass-rate-as-concentration/), [NUM-50](1-numerical/NUM-50-steady-link-api-flux-mass-lost/), [CRASH-12](5-crashes/CRASH-12-steady-link-quality-node-index/), [CRASH-13](5-crashes/CRASH-13-pollutant-flux-before-start/), [API-05](6-api/API-05-quality-getters-wrong-units/), [API-06](6-api/API-06-external-buildup-per-step/), [API-07](6-api/API-07-buildup-getter-sums-land-uses/), [API-08](6-api/API-08-mass-flux-litres-conversion/), [API-09](6-api/API-09-subcatchment-geometry-setters-skip-alpha/), [API-10](6-api/API-10-invert-offset-setters-stale-slope/), [API-11](6-api/API-11-min-slope-percent-vs-fraction/), [API-13](6-api/API-13-api-rainfall-not-wet-step/).
2. **Wrong results in common models, with no warning:** [BND-09](3-boundary/BND-09-duration-floor-drops-last-period/) (the last reporting period is lost for many end times), the subcatchment runoff balance ([NUM-29](1-numerical/NUM-29-zero-roughness-subarea-depression-storage/), [NUM-32](1-numerical/NUM-32-evaporation-and-infiltration-same-water/), [CON-16](2-conceptual/CON-16-subarea-runoff-end-of-step-rate/)), street inlets in EPA's own example ([NUM-25](1-numerical/NUM-25-curb-inlet-capture-nan-in-gutter/), [NUM-26](1-numerical/NUM-26-on-sag-inlet-stale-street-sides/)), [NUM-05](1-numerical/NUM-05-weir-divider-scaled-by-flow-units/) (WEIR dividers depend on the flow units), [NUM-06](1-numerical/NUM-06-mitered-culvert-slope-correction/) (mitered culverts), [NUM-04](1-numerical/NUM-04-si-snowmelt-coefficient-converted-wrong-way/) (SI snow melt 3.24 times too fast), [BND-02](3-boundary/BND-02-tidal-outfall-elapsed-hours/) (tidal outfalls shifted by the start time), groundwater ([NUM-36](1-numerical/NUM-36-gw-outflow-endpoint-trapezoid/), [CON-07](2-conceptual/CON-07-groundwater-et-reduced-by-impervious-evaporation/)), [NUM-41](1-numerical/NUM-41-rdii-rainfall-point-sampled/) (RDII samples the rain gage), storage units ([NUM-12](1-numerical/NUM-12-storage-curve-volume-drops-above-first-point/), [CON-02](2-conceptual/CON-02-min-surface-area-overrides-storage-curve/)), the runoff interface file ([IO-45](4-io/IO-45-runoff-file-evaporation-24x/), [IO-46](4-io/IO-46-runoff-file-groundwater-flow/), [IO-47](4-io/IO-47-runoff-file-groundwater-elevation-sign/)), and [NUM-48](1-numerical/NUM-48-first-order-decay-explicit-euler/) (first-order decay depends on the time step).
3. **The [crashes](5-crashes/README.md)** reachable from an input file.

## OpenSWMM 6.0.0

6.0.0 reproduces 136 of the 200 issues. 24 of those it reproduces on purpose: its source says the legacy behaviour is copied so that the two engines agree to the bit. 64 issues do not affect 6.0.0, usually because its input reader or API was written afresh. Every 6.0.0 patch makes 6.0.0 give the same corrected numbers as the patched 5.3.0, so applying an issue's two patches together keeps the parity tests meaningful; applying only the 6.0.0 patch will make the legacy-parity comparisons of the affected decks differ. [further-findings.md](further-findings.md) also lists defects that exist only in 6.0.0, found while checking it.
