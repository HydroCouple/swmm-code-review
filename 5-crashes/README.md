# Crashes, memory errors and undefined behaviour

[All issues](../README.md)

Each of these reads or writes memory it does not own, or converts a floating-point value that does not fit into an integer type, which is undefined behaviour in C. Every issue's test stops with a sanitizer report or a signal in 5.2.4 or 5.3.0, although CRASH-01, and CRASH-21 on x86-64, give the right results by luck in a release build. They are in the legacy C code that reads and checks the input file (CRASH-02 to CRASH-06, CRASH-08, CRASH-20, CRASH-21), in the simulation (CRASH-01, CRASH-07, CRASH-09 to CRASH-12), in the toolkit API (CRASH-13 to CRASH-17) and in the output-file reader (CRASH-18, CRASH-19). CRASH-11, CRASH-12 and CRASH-14 are 5.3.0 regressions, CRASH-13 and CRASH-15 are in toolkit setters that are new in 5.3.0, and CRASH-20 and CRASH-21 affect only 5.2.4. 6.0.0 reproduces five: CRASH-01, CRASH-07 and CRASH-15 with the same kind of undefined conversion, and CRASH-03 and CRASH-04 without a crash, by accepting the bad input without a message.
