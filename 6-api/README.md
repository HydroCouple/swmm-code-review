# Toolkit API

[All issues](../README.md)

These issues are in the toolkit interfaces rather than the solver: getters that return internal units or raw running sums, setters that return 0 but are ignored or applied wrongly, call-order and error reporting, the binary output reader and the command line exit status. In 5.3.0 most are in `swmm5.c`, `swmm5_stats.c` and the output library's `swmm_output.c`. Eleven are in toolkit functions that 5.3.0 added, six are in 5.2.4 as well, and API-03 (error messages lost in a refactor) is the only 5.3.0 regression. 6.0.0 reproduces nine, mostly in its C API layer (`openswmm_*_impl.cpp`, `SWMMEngine.cpp`) and its CLI. None of them changes the results of a run driven only by an input file: they affect scripts, bindings and coupled models that call the toolkit, and batch jobs that check the exit status.

| ID | Issue | What happens | 5.2.4 | 6.0.0 | Fix |
|---|---|---|---|---|---|
| [API-01](API-01-settings-before-start-reset/) | Forcing values set before swmm_start are accepted, then wiped by swmm_start | Gage rainfall, node inflow or link setting set before `swmm_start` return 0 and are ignored: 1 in/hr of rain gives 0 in/hr, 2 cfs of inflow 0, an orifice set to 0.25 runs fully open. | yes | not affected | Return `ERR_API_NOT_STARTED` for these properties before the run starts |
| [API-02](API-02-call-order-error-sticky/) | A refused out-of-order call blocks the project or aborts the run | `swmm_step` before `swmm_start` makes `swmm_start` fail; `swmm_start` during a run stops it after 10 of 120 steps with no mass balance or report. Only close and reopen recovers. | yes | reproduces | Return the refusal without storing it in `ErrorCode` or `ERROR_STATE` |
| [API-03](API-03-api-error-messages-empty/) | 5.3.0's API error codes have no message text | `swmm_getErrorFromCode` returns `""` for all twelve codes -999901 to -999912, and `swmm_getError` returns the code with an empty message; GUIs and bindings show no error text. | no (5.3.0 regression) | not affected | Replace the stale 501..509 entries in `error.txt` with the negative codes |
| [API-04](API-04-statistics-getters-raw-accumulators/) | Statistics getters return raw accumulators: sums for averages, seconds for hours, feet in SI | 5.3.0 returns J1's average depth as 577 ft (it is 0.76 ft) and time flooded as 2,564 (0.71 h); 6.0.0 returns seconds for hours and ft, cfs, ft³ in SI projects. | no | reproduces | Convert in the getters as the report does: averages, hours, project units |
| [API-05](API-05-quality-getters-wrong-units/) | Ponded concentration and link pollutant load come out of the toolkit in wrong units | In US units 10 mg/L of ponded rain reads 12,335,300 mg/L (NaN when dry), and the setter stores 1.23 million times too little mass; a link load reads 325,831 for 20.327 lb. | no | not affected | Convert with `LperFT3` (and `mcf` for the load); return 0 when dry |
| [API-06](API-06-external-buildup-per-step/) | External pollutant buildup set through the API is added again at every runoff step | One value of 1.0 on 10 ac adds 240 lb over a dry day with a 1 h DRY_STEP and 2,880 lb with 5 min; it reads back as 43,561.6. | no | not affected | Apply as a daily rate over each runoff step; return it unscaled |
| [API-07](API-07-buildup-getter-sums-land-uses/) | The subcatchment buildup getter adds up the land uses' buildup densities | With several land uses it returns the sum of their per-acre buildups: 130 lb on 10 ac (13 lb/ac) reads as 60 lb/ac. | no | not affected | Divide the total buildup by the total land-use area |
| [API-08](API-08-mass-flux-litres-conversion/) | A pollutant mass flux set through the API delivers 28.3 times the requested mass | 10 mg/s set on a node or link gives 10 mg/L in 1 cfs instead of 0.353 mg/L, and 4.491 lb of External Inflow instead of 0.159 lb; `[INFLOWS]` MASS is correct. | no | reproduces | Divide by `LperFT3` when storing the flux (multiply in 5.3.0 getters) |
| [API-09](API-09-subcatchment-geometry-setters-skip-alpha/) | Setting a subcatchment's area, width or slope before the run does not change its runoff | Setters return 0 and read back, but the overland-flow coefficient is not updated: width 500 to 5000 ft keeps the 6.92 cfs peak (should be 19.28); doubled area gives 13.84 cfs, not 7.82. | no | not affected | Call `subcatch_validate()` for the subcatchment in the three setters |
| [API-10](API-10-invert-offset-setters-stale-slope/) | Setting a node invert or conduit offset before the run leaves the slope unchanged | The setters return 0 and read back, but after raising J1 by 1 ft, C1 keeps slope 0.0025 (should be 0.0050) and J1 floods 862 ft³ instead of 0. | no | reproduces | Recompute slope and capacity in the setters (`link_updateSlope()`, `recompute_conduit_slope()`) |
| [API-11](API-11-min-slope-percent-vs-fraction/) | Minimum-slope option mixes percent and fraction, and has no effect when set before the run | 5.3.0 reads `MIN_SLOPE 0.5` as 0.005 and stores a set 0.5 as 50 %; in both engines a value set after open leaves C1 at slope 0.0025, not 0.005, and J1 floods 862 ft³. | no | reproduces | Percent on get and set; recompute conduit slopes (needs API-10) |
| [API-12](API-12-max-route-step-returns-min/) | swmm_MAXROUTESTEP always returns the minimum routing step | It returns `MinRouteStep` (0.5 s) while the engine takes steps up to 30 s; called before the first step, it also changes that step from 0.5 s to 30 s. | yes | not affected | Side-effect-free `dynwave_getMaxRoutingStep()` with Courant factor 1, capped at `ROUTING_STEP` |
| [API-13](API-13-api-rainfall-not-wet-step/) | Rainfall injected on a subcatchment through the API is computed with the dry time step | 2 in/hr for 30 min with a dry gage and 1 h DRY_STEP gives 2.000 in, not 1.000 (1-h gage interval), or -17.25 % runoff continuity error, not -0.10 % (30-min interval). | no | reproduces | Set `IsRaining` when a subcatchment has positive API rainfall or snowfall |
| [API-14](API-14-gage-rainfall-setter-cogage/) | Gage rainfall set through the API is ignored for a gage sharing another gage's series | On a co-gage the setter succeeds but the series rain is used: S2 gets 1.50 in instead of 3.00 in, peak 5.042 cfs instead of 10.084. In 6.0.0 it is ignored for every gage. | yes | reproduces | Check API rainfall before the co-gage; 6.0.0 setter stores the override |
| [API-15](API-15-gage-scale-factor-runtime-change/) | Gage scale factor changed during a run applies late and rescales gages sharing its series | G1's factor changed from 1.0 to 2.0 at 2:30: S1 gets 6.00 in instead of 7.50, and S2, whose gage was not changed, 4.25 in instead of 5.00 (6.0.0: 7.00 and 4.75). | no | reproduces | Rescale the rainfall already read by new/old factor in the setters |
| [API-16](API-16-output-reader-range-checks/) | The output reader returns another element's results for an out-of-range index, period or attribute | Returns error 0 and data from elsewhere in the file: node index 4 of 4 gives C1's flow, link index 3 of 3 the system record, pollutant 0 without pollutants the next node's depth. | yes | not affected | Test `index >= count`, `endPeriod > Nperiods` and `attr` range (after CRASH-19) |
| [API-17](API-17-output-reader-type-code-as-float/) | SMO_getPropertyValue() returns node and link type codes as an integer's bits read as float | Outfall and pump type 1 read as 1.4e-45, storage and orifice 2 as 2.8e-45, and so on; only junctions and conduits (type 0) read right. No error is returned. | no | not affected | Read the type-code slot as `INT4` and convert it |
| [API-18](API-18-cli-exit-code-zero-on-error/) | The command line programs exit with status 0 when the run fails | `runswmm` and `openswmm-legacy` exit 0 after an input error, a missing input file or a run error, so scripts checking `$?` see success; 6.0.0's `openswmm` exits 0 when a step fails (ERROR 14). | yes | reproduces | Return a non-zero exit status when the run failed |
